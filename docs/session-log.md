  - **`communications.type` rejected `'note'` on the live table.** `schema.sql` has always listed it as valid; the live check constraint (created out-of-band during the `comms` → `communications` rename) did not.   - **`calls.id` is a uuid column but the UI sent `call_<timestamp>`**, so every logged call was rejected outright. Now `crypto.randomUUID()`.
  - **`calls` had no `format` or `details` column**, though `EngagementCall` has carried both since calls were built and the scheduling form writes both — so every schedule PATCH failed on the whole payload, taking `scheduled_at`, `status` and `scheduled_tz` with it. Scheduling a call had never persisted. Masked by the id bug (the insert failed first) and invisible to the static audit because `updateCall` passes its patch through a spread.   - **`upsertContact` was an upsert**, so Postgres built the insert branch before resolving the conflict and any partial patch died on `first_name NOT NULL`. Contact edits and every per-field contact write failed. Now a real UPDATE that asks for the row back and throws when nothing matched.

Routed through `deleteContact` and a new `setPointOfContact`. Also closed the two in-flight races this exposed: a contact removed before its INSERT returned left the row behind, and a point-of-contact click in the same window was dropped — both now queued against the temp id and applied once the real id is known.

Stages set by hand for thank-you, testimonial, social media and follow-up vanished. Read now starts from the stored column and lets the derived values win only where they are authoritative.
  - **The timeline "wake" button sent an empty patch.** `updateComm` spread all four next-step keys through `?? undefined`, so un-snoozing serialised to `{}`; PostgREST answered 204 and nothing changed. Now sends only supplied keys and maps `undefined` to null so a field can actually be cleared.

Harmless while section removal reverted on reload; once removals persisted, the document sent to a client permanently disagreed with what the team saw. Both levels are now honoured — an individual field by its own key, a whole section by `_section_<name>` — with no signature change, since the engagement already carried `field_statuses` unread. The MCP server's `generate_briefing_pdf` inherits it. - What I did (whole-branch summary — the contract-drafting feature, built across several sessions on this branch):
  - **Contract data layer + numbering**, mirroring invoicing: a `contracts` table with sequential `CON-####` numbering via a `create_contract` Postgres RPC, drafted-vs-received origin, per-engagement documents (an engagement can hold several), signed-file upload, and status mirrored onto the engagement's `contract_finalized_at`/`contract_sent_at`/`contract_signed_at` columns. All access goes through `/api/contracts/*` routes on the service-role gateway (`src/lib/contracts.ts` server-only, `contracts-client.ts` for the browser).
  - **Editable template system**: a `contract_templates` table holds the legal/business body as an ordered list of typed blocks (`heading`/`paragraph`/`key_value`/`bullet_list`/`line_list`/`book_section`) with `{{merge_field}}` substitution. Structural elements (letterhead, Program Details, Project Scope, Authorization/signatures) stay in the renderer. Template editor pages under `/contracts/templates`. Each contract freezes the template's blocks into its own `blocks_snapshot` at creation, so editing a template never retroactively changes an already-created (possibly signed) contract; renderer/structural changes still apply to all on re-download.
  - **PDF renderer rewrite** (`src/lib/documents.ts`): normalized to one font/size (bold + caps for emphasis only), stripped the accent color to match the invoice's plain palette, currency-formatted fees, conditional data-driven Book Fee section (omits entirely when there's no order; Client buys direct from the vendor so it never touches the total), real wrapped-height reservation for run-of-show lines, a Unicode-punctuation sanitizer so exotic dashes/quotes stop rendering as "?", a signature block that pulls in the client company and gives each party a signature line plus a separate printed-name-&-title line, a fixed `setLineHeightFactor` (root cause of length-dependent paragraph-spacing drift), and finally one flat spacing rhythm across the whole document with page-break reservations that stop a section heading from being orphaned at a page bottom.
  - **Status workflow**: `draft → finalized → sent → signed`, each stage timestamped, with full bidirectional reversal (un-finalize / un-send / un-sign) that clears only the stages stepped out of and preserves the rest; the engagement mirror follows suit.
  - **UI**: Contracts list page (search, status-filter tabs, pagination), a New Contract modal (tied to an engagement, template picker), an Edit Contract Details modal (all snapshot fields incl. the book-order toggle), and delete-a-contract with a close-aware confirm that re-derives the engagement's contract mirror from whatever documents remain.
