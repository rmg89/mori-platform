## Overview

CRM and business-operations platform for booking and running Mori Taheripour's speaking engagements, from first inquiry through post-event wrap-up and payment.

## Features

### Shipped

- **Pipeline**: prospects → engagements → wrap-up, each with its own list view (`src/app/prospects`, `src/app/engagements`, `src/app/wrap-up`) and a detail page per record (`[id]/page.tsx`)
- **Dashboard** (`src/app/dashboard`) — business snapshot: counts, upcoming events, items needing response, unpaid invoices, stale prospects
- **Companies & contacts directories** (`src/app/companies`, `src/app/contacts`) with per-record detail pages
- **Archive** (`src/app/archive`) for engagements taken out of the active pipeline, with a required reason
- **Advance sheet / briefing doc** per engagement (`src/app/engagements/[id]/advance-sheet`) — purpose, audience, venue/travel logistics, run of show, moderator/panelist info
- **Invoices** (`src/app/invoices`, `src/lib/invoices.ts`) — sequentially numbered via a `create_invoice` Postgres RPC, status tracked against per-engagement payment fields; deposit invoices supported separately from final invoices
- **PDF generation** (`src/lib/documents.ts`, jsPDF) — contracts, briefing docs, invoices, deposit invoices
- **AI email reply drafting** (`src/app/api/ai/email-reply`) and **Instagram caption generation** (`src/app/api/ai/instagram-caption`) via Claude
- **Automatic AI engagement scans** (`src/lib/ai-scan.ts`) — on decline, on move-to-confirmed, and on move-to-wrap-up, Claude flags which contract/materials/post-event items likely apply and drops a summary into that engagement's briefing notes
- **MCP server** (`src/app/api/[transport]`) — 29 tools exposing the full pipeline (list/get/update engagements, contacts, companies, calls, materials, briefing notes, invoices, PDF generation, plus `move_engagement_backward`/`unarchive_engagement`) for direct use by Claude. Requires a bearer token on every request (added 2026-07-10; fails closed if no token env var is set). Accepts either the shared `MCP_SECRET_TOKEN` or, since 2026-07-27, any per-person token in the optional `MCP_TOKENS` var (see the multi-token entry below)
- **Settings** (`src/app/settings`) — invoice letterhead / business profile editing (`src/lib/business.ts`, Billing tab), integrations status list; user management is a placeholder
- **File upload** endpoint (`src/app/api/upload`)
- **New Inquiry** (`src/components/NewInquiryModal.tsx`, launched from Prospects and Dashboard) — creates a prospect with search-or-create organization linking, AI-assisted website lookup for new organizations (`src/app/api/ai/enrich-company`, Claude + web search, never fabricates), and support for adding multiple contacts, each optionally linked to an existing or new company
- **Add Company** (`src/components/AddCompanyModal.tsx`, launched from the Companies page)
- **Delete company / delete contact** — typed-confirmation delete that unlinks (rather than blocks on) any referencing engagements/contacts/comms (`supabase/migrations/allow_delete_companies_contacts.sql`)
- **"Current" engagement tracking** (`src/lib/utils.ts` → `isEngagementCurrent`) — engagements with an `event_date` today or later are flagged "Current" on the company detail page and filterable on the Companies list
- **Invoice finalize workflow** — `draft → finalized → sent → paid`, plus an invoice edit modal (`src/components/InvoiceEditModal.tsx`) for correcting snapshot fields after creation
- **Un-archive, move backward, move to Wrap-Up manually** (`src/lib/pipeline.ts`, `src/components/UnarchiveButton.tsx`) — an archived record can be restored via a button on the Archive list or any detail page; a confirmed engagement or wrap-up record can be moved back one pipeline stage (restoring the frozen `prospect_step` from its snapshot); an engagement can be moved to Wrap-Up manually ahead of the automatic date-based transition. All three also exposed as MCP tools.
- **Add Contact** (`src/components/AddContactModal.tsx`, launched from the Contacts page) — standalone entry point for a contact independent of any engagement, with inline company search-or-create; sortable columns on both the Contacts and Companies list pages; a "Companies" nav link on the Contacts page mirroring the existing "Contacts" link on Companies.
- **Stage History nav + read-only snapshot views** (`src/components/StageHistoryNav.tsx`, `ProspectSnapshotView.tsx`, `EngagementSnapshotView.tsx`) — wired into `prospects/[id]`, `engagements/[id]`, `wrap-up/[id]` so a record that's moved past a stage shows a frozen, visually-faithful replica of that stage's live page instead of the stale live template, plus a "Stage History" pill nav to jump between them.
- **Supabase CLI migration tracking** — see Decisions below.
- **Global search bar wired up** (`src/components/layout/GlobalSearch.tsx`, replacing a dead placeholder `<input>` in `AppShell.tsx`) — queries engagements, companies, and contacts live from the store and shows a grouped results dropdown that navigates to the matching record. `/test`-reviewed, merged `wire-up-search-bar` to `main` 2026-07-16.
- **Server-side Supabase gateway** — all Postgres table access moved off the browser anon key onto server-side API routes (`src/app/api/{engagements,contacts,companies,communications,calls,business-profile,invoices,review-items,briefing-notes}/**`) using the service-role client (`supabaseAdmin()`, previously dead code). `src/lib/db.ts`/`business.ts`/`invoices.ts` are now server-only; new client wrapper files (`db-client.ts`, `business-client.ts`, `invoices-client.ts`) preserve the exact old call signatures for `store.tsx` and other client components. `/code-review`-reviewed, merged `secure-supabase-rls` to `main` 2026-07-16; `briefing-notes` added to the gateway during `fix-engagement-detail`'s merge reconciliation the same day.
- **Inbound-email tracking + AI parsing, Phase 1** (`review_items` table, AI-parsing module `src/lib/ai-email-parse.ts`, token-gated `/api/email-sync/ingest` endpoint, real persistence for the Review page's confirm/dismiss — previously local-state-only, reset on refresh) — `/test`-reviewed, merged `email-review-pipeline` to `main` 2026-07-16. Fails gracefully with no `ANTHROPIC_API_KEY` set. Live Microsoft Graph sync itself is a separate follow-up, blocked on an Azure AD app registration from the client — see Maybe/someday.
- **RLS enabled, true default-deny for `anon`** on all 10 live tables — pushed 2026-07-16, same session as the gateway above. Turned out to need a second fix: 7 tables (`briefing_notes, calls, communications, companies, contacts, engagements, materials`) had leftover fully-permissive policies from an earlier, abandoned RLS attempt, dormant while RLS was off, which silently reactivated and defeated the first migration's "zero policies = default-deny" assumption. Found by directly testing the anon key against the live API rather than trusting the migration's success message, diagnosed with temporary `SECURITY DEFINER` RPCs (no Docker/psql access on this machine), fixed by dropping the legacy policies, verified with real anon-key read/write attempts against production. See Decisions.
- **Briefing Document / materials fixes** (`fix-engagement-detail`, merged `main` 2026-07-16) — materials added via the `add_material` MCP tool with a link now correctly show as received instead of overdue; briefing notes render newest-first; adding/resolving/deleting/unresolving a briefing note actually persists to Supabase (previously silently local-state-only); briefing notes now go through the server-side gateway like every other table.
- **Call-tracking fixes on the Prospects list/detail page** (`fix-call-tracking`, merged `main` 2026-07-17) — a prospect with a scheduled call no longer misclassifies as "Unmanaged"; call info (link/phone/location) is editable independent of the scheduling flow; rescinding an accidental "Completed" click back to "Scheduled" no longer risks losing the date; timeline items can be deleted; a comm's `next_step` shows as a flagged badge in the timeline instead of being silently captured; multi-paragraph notes keep their formatting. `deleteComm` goes through the server-side gateway like every other table, and comm ids are now real UUIDs sent to Supabase on insert (see Known bugs) so deleting a just-logged comm doesn't 500.
- **Multi-token MCP auth** (`add-mcp-multi-token-auth`, merged `main` 2026-07-27) — the MCP endpoint now accepts multiple valid bearer tokens so each person (Chi, Mori, etc.) can get their own, revocable independently. New optional `MCP_TOKENS` env var: comma-separated `name:token` pairs (e.g. `chi:abc,mori:def`), parsed defensively (tolerates unset/empty/whitespace/malformed entries, splits on the first `:` only). The legacy `MCP_SECRET_TOKEN` remains a first-class path, checked first, unchanged. Comparison stays constant-time (`timingSafeEqual`), the 401 failure response is unchanged, and each authenticated request logs the matched entry name (or `legacy`) — never the token. Only `src/app/api/[transport]/route.ts` changed. **Post-merge setup still required for anyone new to connect: set `MCP_TOKENS` in Vercel and redeploy.**
- **Contract drafting** (`add-contract-drafting`, merged `main` 2026-07-28) — full contract lifecycle mirroring invoicing. A `contracts` table with sequential `CON-####` numbering (`create_contract` RPC), drafted-vs-received origin, multiple documents per engagement, signed-file upload, and status (`draft → finalized → sent → signed`) with bidirectional reversal (un-finalize/un-send/un-sign) mirrored onto the engagement's `contract_finalized_at`/`contract_sent_at`/`contract_signed_at` columns. An editable **template system** (`contract_templates`, block-based content with `{{merge_field}}` substitution, editor at `/contracts/templates`); each contract freezes its template into a per-row `blocks_snapshot` so later template edits never alter existing contracts. A rewritten jsPDF renderer (`src/lib/documents.ts`): plain letter-like styling, currency-formatted fees, conditional data-driven Book Fee section (informational — never added to the total), a signature block that fills in the client company with a signature line plus a printed-name-&-title line, a Unicode-punctuation sanitizer, and one flat spacing rhythm with orphaned-heading prevention. Contracts list page (`src/app/contracts`) with search/filter/pagination, a New Contract modal, an Edit Contract Details modal, and delete-with-mirror-recompute. All table access is server-side gateway only (`src/lib/contracts.ts`/`contract-templates.ts` via `supabaseAdmin()`, fronted by `/api/contracts/*` and `/api/contract-templates/*`); RLS is default-deny for `anon` on both tables.

- **MCP token accepted on the URL, for claude.ai connectors** (`mcp-url-token` + `update-connector-guide`, merged `main` 2026-07-31) — claude.ai custom connectors cannot send request headers (Advanced settings offers only an OAuth Client ID/Secret), so the documented `Authorization: Bearer` setup was impossible to complete and every connection attempt failed with an OAuth registration error. `/api/[transport]` now also reads the token from `?t=` (or `?token=`) on the URL, checked after the header so Claude Code / Claude Desktop are untouched. Both `MCP_SECRET_TOKEN` and `MCP_TOKENS` work through either presentation; the compare is still constant-time, the `401` body byte-identical, and only the matched label is logged. Every presented credential is tried rather than stopping at the header, so a client's own unrelated `Authorization` header can't shadow a valid URL token. **The URL is the secret** — it appears in Vercel request logs, so issue one `MCP_TOKENS` entry per person and rotate individually. Setup guide for non-technical users lives in `docs/connector-setup.md`.

- **Error tracking and user problem reports** (`error-reporting`, merged `main` 2026-08-11) — nothing recorded failures for the two live users before this: `app/error.tsx` logged to a console nobody reads, the client data layer threw into unhandled rejections, and three API routes had no error handling at all. New `error_reports` table (default-deny RLS, `service_role` only) behind `/api/errors` — validated, rate-limited and size-capped ingest, list, and triage by id or fingerprint. Reports group by a normalized fingerprint (uuids/numbers stripped) so one cause reads as one row with a count. Browser capture (`src/lib/error-reporting.ts`) covers render crashes, unhandled rejections, window errors and every failed `/api` call, carrying page, action, HTTP status, browser, a stable session id and a breadcrumb trail; `app/global-error.tsx` added for root-layout failures. Server capture (`src/lib/error-log.ts`) via `serverError()` in 40 route catch blocks, `withErrorLogging()` on the three routes that had none, and the MCP route's 29 tool error paths. Framework control-flow throws (`redirect`/`notFound`/dynamic-usage) propagate rather than being recorded. A **"Report a problem"** button on every page attaches the session's recent errors so the user only has to type one sentence, and **Settings → Errors** lists everything grouped by cause with expandable detail and resolve/reopen. Every captured failure also raises a plain-language notice to the user, and a resource that fails to load names itself in a persistent banner while the rest of the app keeps working.
- **Silent-failure audit** (same branch) — twelve paths that failed with no signal anywhere, closed. `fetchAllEngagements` discarded the errors from five of its six reads, so a dead `contacts` table would have rendered as every engagement having no contacts, on every page, with a clean console; `ai-scan.ts` returned an empty patch on four failure paths, indistinguishable from "the AI found nothing to flag"; `insertContact`/`fetchCompanies`/`fetchReviewItems`/`fetchReviewItemExtracted` logged and returned `null`/`[]` on both server and client and now throw; the inbound-email parser and company enricher swallowed unparseable AI output; a contract PDF rendered unsigned when the signature image failed to load. Four byte-identical copies of the browser fetch wrapper were consolidated into `src/lib/api-client.ts`.

## Known bugs

- **Nothing detects silently *wrong* behaviour.** Error tracking (2026-08-11) captures anything that throws or returns a non-OK response, but a value that saves incorrectly, or a control that does nothing because of a logic bug, produces no error and no report. That class is only ever found by a human using the app — which is what the `fix-saving` work was.
- The four AI routes call `await req.json()` outside their try blocks, so a malformed request body produces an unlogged 500 rather than a clean `{error}`. Narrow in practice, since only this app's own client calls them, but it's the same gap that was fixed on `POST /api/contacts` in 2026-07-16.
- `error_reports.severity` distinguishes `error` from `warning` and is written correctly, but the Settings → Errors list doesn't render the two differently — a warning shows with the same red treatment as a hard failure.
- **MCP auth (`401` paths) has not been re-verified since `src/app/api/[transport]/route.ts` changed on 2026-08-11.** Only the tool error-return paths were touched, and the auth functions were not, but Vercel Deployment Protection means MCP is only testable against production. Post-merge check, not a pre-merge one.
- The primary checkout's `.env.local` has `MCP_SECRET_TOKEN=""` (two quote characters, empty) from the documented `vercel` CLI clobber trap. Production is unaffected, but local MCP dev fails closed until the real value is restored — the plaintext isn't recoverable from this machine, so it has to come from the Vercel dashboard or be rotated.

In order of how much data they cost: **timeline "Note" entries** (live `communications_type_check` rejected `'note'` while `schema.sql` allowed it), **every logged call** (`calls.id` is `uuid`, UI sent `call_<timestamp>`), **every call schedule** (`calls` had no `format`/`details` column, so the whole PATCH 400'd including `scheduled_at`), **post-event notes** (no column; the handler wrote to `notes`, destroying the general notes field on every keystroke), **proposed dates** (no column, no write path at all), **contact edits** (`upsertContact` was an upsert, so partial patches died on `first_name NOT NULL`), **removing a contact** and **setting the point of contact** (both routed through `updateEngagement({ contacts })`, which strips the array before writing), **wrap-up stages** (written, then discarded on read by a derived value), **the timeline "wake" button** (serialised to `{}`, 204, no change), and **removing a briefing-doc section** (`useState`-only). Collapsing onto one store is one-way; undecided as of 2026-08-10.

- **No delete path exists for invoices, materials, or review items**, and **no edit path for a timeline note's body or a briefing note's body** — a typo in a logged note is permanent, and can only be removed by deleting the whole entry. Found by the 2026-08-10 coverage audit.

- **Calls only render on the prospect detail page.** Once a prospect is confirmed, its call history is not visible anywhere in the live UI.

- **Columns holding real production data that no page displays**: `engagements.media_links` (2 rows), `outstanding_items` (3), `travel_destination` (5), `communications.channel` (26), `to_name` (5). The last two are written by nothing and read by nothing — the data is stranded. `av_needs` is MCP-writable with no UI and no data yet.

- **The live DB rejects two values the TypeScript unions allow**: `engagements.prospect_step = 'confirmed'` and `contacts.status = 'prospect_expired'`. Neither is currently reachable (the confirm flow writes `null`), but the "Prospect — Expired" filter on the Contacts page can therefore never match anything.

- `Engagement` declares three properties that are not live columns and that nothing reads: `ai_created`, `human_confirmed`, `special_requirements`. Type noise, not a runtime bug.

## Decisions

- Canonical Vercel project for this repo is `team-taheripour-platform`, not `mori-platform` — confirmed 2026-07-10. The local Git repo and CLI are linked to it.
- Local dev, Preview, and Production all share one Supabase project and one set of credentials — confirmed 2026-07-10. There is no separate dev/preview database.
- Adopted real Supabase CLI migration tracking 2026-07-15 (project ref `jwdxuorpcppsjcomvhch`) after repeated "was this migration actually run" incidents. All 15 pre-existing migration files were renamed to CLI-compliant timestamps and reconciled against the live database via `supabase db push`. Going forward: `supabase migration new <name>` for schema changes, `supabase db push --dry-run` to preview, `supabase db push` to apply — additive/idempotent changes applied without asking (mirrors the git branch-push convention), destructive/one-way changes always confirmed first.
- Built everything downstream of "an email arrived" (parsing, contact/company matching, review-queue persistence) before live Microsoft Graph sync exists, rather than waiting — confirmed with the user 2026-07-16. Live Graph OAuth/webhook sync is deliberately a separate, later branch once the client provides Azure AD app credentials (client ID, tenant ID, secret, `Mail.Read` application permission + admin consent); nothing about the parsing/matching/review logic should need to change when that lands, since `/api/email-sync/ingest` is the seam both a manual test call and a future webhook call through.
- Merged `email-review-pipeline` to `main` the same session it was built, rather than leaving it open for the ~2 weeks until the client meeting that unblocks Graph sync — confirmed with the user 2026-07-16. Reasoning: the branch is complete and safe standing alone (fails gracefully with no AI key configured), the Review-page persistence fix is a real bug fix worth shipping now, and holding a branch open for two weeks only accumulates merge drift against a `main` that other concurrent sessions keep moving.
